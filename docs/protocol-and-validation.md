公共 RX 为 `48090001-1a48-11e9-ab14-d663bd873d93`，TX 为 `48090002-1a48-11e9-ab14-d663bd873d93`。双金标版、W830NB 和 Lolli ANC 的官方产品配置列出 RFCOMM 服务 `edf00000-edfe-dfed-fedf-edfedfedfedf`。软件优先尝试已配对设备的 RFCOMM；存在对应广播时允许转用 BLE。

公司编号 2016 的广播制造商数据中，开头六字节用于关联经典蓝牙地址，最后两字节提供协议版本和加密方式。未获得此元数据时，只使用 D8 只读请求尝试 v1、v2 明文和 v2 XOR；能力结构有效后才继续。未知版本或加密方式拒绝写入。

## 报文

- v1：`AA | (payload 长度 + 1) | command | payload | sum16`。校验为前面字节之和加 `0x2019`，大端两字节。
- v2：`AA | EC | command | length_hi | length_lo | payload | sum8`。校验为前面线缆字节之和的低八位。加密代码 16 对 payload 逐字节 XOR `A5`；代码 0 为明文。
- 返回头识别 `BB` 和 `CC`。解析器支持分片、合并报文、校验失败后的重同步与缓冲上限。
- 请求串行执行。F0/F1 额外关联子命令编号。超时命令在当前连接内停用，防止迟到回复误配到重试请求。

## 功能边界

本节保留早期基础功能说明。0.3.0 的完整新增控制、协议范围与验证边界以 [功能覆盖表](feature-coverage-0.3.0.md) 为准。


| 功能 | 读取 | 写入 | 验证与限制 |
|---|---|---|---|
| 能力 | D8 | 无 | 决定菜单与可写范围；v2 ANC 类型以 CC 返回为准 |
| 固件 | C6 | 无 | 仅显示与备份匹配 |
| 单机电量 | D0 | 无 | 大于 100 不伪装成有效百分比 |
| 双耳 / 新电量 | F2 | 无 | 区分左耳、右耳和连接状态；充电盒需能力标志 |
| 声音模式 | CC | C1 | v1 发送模式；v2 发送类型与模式；仅已映射类型开放 |
| 环境声 | CC | C1 | 适配类型的线缆值 3–9，界面显示 −3 至 +3 |
| 预设 | D5 | C4 | 适配 EQ 类型 1、2、3、4、6、7、8、50；自定义频段详见 0.3.0 覆盖表 |
| 游戏模式 | 08 | 09 | 0 / 1；需能力标志与有效读回 |
| 提示音量 | 05 | 06 | 0–15；需能力标志与有效读回 |
| 双金标版降噪键 | F0 `0A` | F1 `0A mask` | 触控类型 15；mask 为 3、5、6、7，至少两种模式 |
| 简单触控分配 | F0 `slot` | F1 `slot value` | 类型 5、6、8、9、13、14、23；新增类型 30 和嵌套动作见覆盖表 |
| 双设备连接 | 7C | 7D | D8[20] bit7；校验旧格式或带类型格式；TWS 需双耳在线；批次末尾写入；断连后重新核对 |
| Lolli 入耳检测 | FB | FC `group mode` | 能力位开启且类型为 1–4；未识别类型不开放 |

设置备份包括设备地址的摘要，不保存明文蓝牙地址。不同设备、型号、固件、能力、协议、ANC / 入耳检测类型或预览状态的备份不能混用。

所有设置批次先完整验证参数、读取当前设置并写入备份文件。备份失败时不发设置命令。每个设置写入后进行独立读取；读回失败或不一致会停止批次，并锁定后续写入，直到重新连接。已成功写入的前序设置不会自动撤销，保存的备份用于人工检查后恢复。

## 验证证据

0.3.0 共 60 项离线测试；早期基础覆盖 117 条完整公开抓包、两种报文与 XOR、校验损坏、分片与合并、未知型号与功能、单耳和未知电量、设置范围、备份失败、部分写入停止、导入身份校验、取消以及佩戴检测类型。

原生预览检查为三款设备分别生成浅色与深色页面，并检查内置许可证、图标和布局。独立启动测试仅复制 EXE，清空用于查找 .NET 的环境变量与路径，并检查 .NET 主机日志，确认从包内运行时启动及解压原生 WPF 组件。

这些结果证明软件能构建、启动和处理所覆盖的报文与失败情况。它们不能证明 Windows 蓝牙驱动、实际固件回复、射频连接或长期运行均正常。没有真实设备写入测试，也没有听感、音质、延迟或续航测量。

普通启动另外检查了实际窗口：工具启动的受限进程最初无法在默认用户临时目录创建解压暂存目录（错误 5）。将独立验证中提取的五个原生组件按 SHA-256 校验后放入本 EXE 对应的默认缓存，普通无参数启动成功。没有修改系统 ACL、注册表或持久环境变量。隔离目录的首次解压已经通过；默认临时目录的首次解压受测试进程权限影响，不能据此声称已验证任意机器的首次启动。0.2.0 的默认缓存也按此方式验证，详见 `native-startup-check-0.2.0.json`。

## 实机到手后的验收

1. 分别连接 W820NB、W830NB 和 Lolli ANC，保存诊断，确认型号、协议、能力与真实电量。
2. 每次只改一个低影响设置，核对耳机实际行为、软件读回和官方 App 显示。
3. 测试关闭窗口、耳机断电、单耳使用及重新连接后的状态。
4. 测试双设备开启 / 关闭、手机与电脑切换、LDAC / 空间音效交互及写入重启后的实际状态。
5. 核对同设备备份恢复。保留未适配功能，不因同系列名称而扩大写入范围。

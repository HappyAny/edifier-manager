# 0.2.1：Lolli ANC 降噪校验与双设备入口

2026-10-26。针对 0.2.0 实机使用中“声音设置读回不一致”和双设备连接卡片消失的反馈。

## 证据与原因范围

本机设置备份记录 Lolli ANC 固件 1.0.9、协议 v2 / XOR 0xA5、ANC 类型 23、入耳检测类型 4。降噪模式记录仅有模式值；环境声模式另有增益 6。这些是软件保存的读取结果，不是原始蓝牙抓包。诊断中尝试只读连接，先因已有管理连接占用而失败，随后设备未提供管理服务，未对真实设备发送设置命令。

旧版在声音写入后仅核对一次状态，无法容忍设备返回切换前的状态。恢复设置时还会在已离开环境声模式后要求读回环境声强度。修复覆盖这两类情况；本次未复现原始报错的完整实机时序，因此不能把延迟认定为已经实测确认的唯一原因。

官方 EDIFIER Connect 8.5.3 的 `CommandManager.setANCCommand` 和 `CommandParser.parseAnc` 已核对：v2 写入 C1 的负载为 `[类型, 模式, 可选增益]`；CC 读取仍保留类型字段。类型 23 的模式为 1 降噪、2 环境声、3 降噪关闭。本次不改变这一映射。

## 修正

- 声音写入仍只发送一次。第一次校验前等待 200 ms，之后间隔 300 ms，最多读取 6 次 CC；只读重试不会重发设置命令。
- 环境声强度恢复先在环境声模式确认，再切到最终模式。离开环境声模式后，缺失强度不再造成错误。
- 真实不一致仍阻止后续写入。界面显示最后有效状态，错误中带目标模式和读回模式；诊断记录 C1 / CC 的状态负载和每次校验，不包含蓝牙地址。
- Lolli ANC 设置页保留双设备连接卡片。未上报独立开关时显示配对步骤和系统蓝牙设置入口，不伪造开关或两台设备在线状态。
- Lolli ANC 预览采用此次已记录的能力组合。触控类型 30 和 EQ 类型 50 仍未适配，不在预览中假设它们可用。

## 双设备连接依据

[Lolli ANC 官方说明书](https://cn-oss.edifier.com/Uploads/images/2025/07/22/2025072215432017531702001860.pdf) 的“ 双设备连接”段给出 A 配对 → B 配对 → A 手动重连，并说明再次开机回连最后两台设备，没有要求先在 App 打开开关。

官方 App 的可配置开关入口由 D8 第 20 字节（零起始）的 bit7 控制。本机记录未设置该位；旧版把“未提供开关”与“隐藏整个双设备功能说明”绑定，是入口消失的直接原因。仍只对成功读取的已适配开关格式开放 7D 写入。

## 验证边界

回归覆盖延迟读回、非环境声模式不返回增益、跨模式恢复、真实不一致、错误增益、无效回复以及无变化操作。测试能力输入来自本机读取记录，切换时序由测试程序模拟。具体结果见 `offline-tests.json`、`window-close-tests.json` 和 `portable-check-0.2.1.json`。

尚未完成新版真实降噪切换与两台设备音频切换验证。原有版本收据保留作历史记录，不作为当前版本验证结果。

# 0.3.0 功能覆盖与证据边界

本次按“能补齐的都完全补齐”扩展独立 Windows 工具。覆盖已取得明确命令、范围和读取校验方式的本地功能，不用模拟数据宣称硬件已支持或实测通过。

## 各型号

| 项目 | W820NB / 双金标版 | W830NB | Lolli ANC 1.0.9 已知能力 |
|---|---|---|---|
| 降噪 / 环境声 / 游戏 | 读取类型后开放 | 读取类型后开放 | 已有真实读取记录；新增写入未实测 |
| 预设 EQ | 原版可能不提供；双金标按返回类型 | 预设与自定义模式按返回类型 | 类型 50 五档已实现 |
| 自定义频段 | 仅返回自定义能力与有效 43 状态时 | 完成编辑器与 1–18 类型解析 | 类型 50 不提供自定义频段入口 |
| 触控 / 按键 | 双金标类型 15 降噪循环 | 不套用其他型号的按键格式 | 类型 30 六个位置及降噪子选项已实现 |
| 新版提示音 | 按能力与 86 回复类型 | 按能力与 86 回复类型 | 能力位开启；等待实机读取 86 确认具体类型 |
| 灵敏度 | 必须上报 B17 bit3 | 同左 | 已读记录未上报，不能把 B19 的触控标志当成支持 |
| 改名 / 定时 / 关机 | 能力与读取双重约束 | 同左 | 已读记录上报支持；功能已实现、未实机写入 |
| 双设备 | 不从家族名称推断 | 已实现配置开关 | 官方配对指引；未上报独立开关 |
| LDAC / 防风噪 / 无音频关机 | 按独立能力与读取开放 | 同左 | 本次已读能力未上报这些独立设置 |
| 寻找耳机 | Windows 音频连接可用时 | 同左 | 可选左右或双通道，不等于定位或离线查找 |
| 清除配对 / 出厂重置 | 仅能力明确开启时 | 同左 | 当前记录未上报，不能强行显示按钮 |

“未上报”只描述该记录的能力位。设备本体可能通过实体按键提供某些功能，不能据此证明硬件不具备该功能。

## 协议与独立实现

协议事实来自官方 EDIFIER Connect 8.5.3 本地互操作研究。安装包来源与 SHA-256 见 `protocol-and-validation.md`。不分发官方 APK、反编译源码或商标图片。已有 V1 抓包来自 MIT 许可的 mEDIFIER，并保留许可。

| 功能 | 查询 | 设置 / 动作 | 约束 |
|---|---|---|---|
| Lolli 预设类型 50 | D5 | C4 value | 0 经典、1 重低音、2 清澈人声、3 高音增强、4 剧院 |
| Lolli 触控类型 30 | F0 slot | F1 slot action [mask] | slot 1/2 双击、3/4 三击、8/9 长按；action 5 附降噪循环 mask；位序采用 ANC 选项顺序，选两至三项 |
| 新版提示音 | 86 | 87 group position value | 保留 group；按已知格式确定分项和范围，不把所有回复当音量 |
| 旧版提示音开关 | F9 | FA value | 0/1，与旧版 05/06 音量分开 |
| 灵敏度 | FD | FE [index] value | V1 0–31；V2 index1 0–31、index2 0–15；仅 B17 bit3 |
| 名称 | C9 | CA UTF-8 | 按 B3 限制字节数；严格解码与读回；摘要身份索引保证改名后识别 |
| 定时关机 | D3 | D1 hi lo / D2 | 大端分钟数；允许读回自然减一分钟；不自动恢复旧倒计时 |
| 无音频自动关机 | D7 | D6 value | 0/1，需 B8 支持 |
| LDAC | 48 | 49 value | 0/1/2；独立确认；断开或无法读回不算成功 |
| 风噪 | 5C | 5D value | 0/1，需 B18 bit4 |
| 自定义 EQ | 43 | 44 band / 45 reset | 根据 group 解码 4 或 6 字节频段，7/12 保留 bank；逐段验证，失败不继续 |
| 设备管理 | 能力 D8 | CD / CF / CE / C7 / 07 | 分别断开音频、配对、关机、清配对、出厂设置；无能力不开放；仅收到应答不宣称物理动作完成 |

重点核对的官方实现位置：`D8Bean`、`CommandManager`、`CommandParserHelper.getSameDataToP1E/getEQBean/getTapSettingOptions`、`ControlSettingAc.click$getMultiValue`、`BeepGroup`、`Beep`、`CommandParseManager.parseCustomEq/parseCustomEqFreqPoints`、`ProtocolConfigurations.getCustomEqConfig`、`CommandPayloadManager.getCustomEqSet`。代码为本项目重新实现。

寻找耳机遵循官方 App 的音频播放方式；本项目生成自己的提示音。通过 Windows `DRV_QUERYFUNCTIONINSTANCEID` 把 waveOut 设备对应到已选择的 Core Audio 端点，找不到精确端点就停止，不使用默认扬声器。8 秒自动停止，关闭管理连接或程序取消播放，不调整系统音量。系统单声道设置可能使左右通道合并。

## 明确未实现的外部链路

- 固件 OTA：本地研究能识别升级能力，但尚无针对这些芯片、固件签名、分区和掉电恢复的完整已验证升级链路，使用官方 App。
- 云端 AI 翻译、账号与语音包下载 / 安装：依赖官方应用及服务，不借用或复制用户凭据，不把入口写成已经实现的本地功能。
- 未知协议类型：不猜测格式；功能状态页显示未读到已识别状态。成功读取的其他功能仍可使用。
- Lolli 的独立双设备开关：实际能力没有报告该设置。保留完整配对引导；不生成虚假开关或连接数量。

## 验证

本次协议测试覆盖 60 项，包括原有 117 条公开抓包和新增功能的正常流程、越界、缺失读回、备份失败、部分写入停止、重新连接要求、改名索引、触控嵌套恢复、提示音类型、EQ 逐段验证及左右提示音样本。

7 项真实 WPF 测试包含：Lolli 六个手势、降噪循环、提示音量、改名、定时、五档 EQ 的控件操作；W830 自定义 EQ 和双设备开关；未连接、重复关闭、等待释放及清理异常。33 张预览图覆盖深浅色、三款布局及新增页面滚动区域。单 EXE 在隔离目录和空 .NET 查找路径下启动，验证 9 档图标、8 份内置许可和嵌入运行时。

2026-10-26 的只读实机探测显示 Lolli ANC 当时未连接，因此没有建立连接或发送设置。本次新增功能没有真实设备写入、声音收听、固件升级或双设备切换验收；预览值不作为硬件证据。

研究和私人设备记录留在原项目，交付包排除 `research`、`artifacts` 与备份目录。沿用项目已有归档范围说明；本次没有授权独立知识库索引同步。
